# 网页会话开发与验收

更新时间：2026-11-06。新 Key 已通过官方认证；真实网页流式回答、追问、参考性质与未知职责处理、作品引用打开均通过。完整故障与跨入口集成验收仍待 M5。

## 已实现

- 服务端 `CHAT_MODE`、`LLM_BASE_URL`、`LLM_MODEL`、`DEEPSEEK_API_KEY`、`LLM_TIMEOUT_MS`；默认 DeepSeek，未配置密钥时明确返回 503，不自动切换本地演示。
- 根据当前公开介绍与作品检索资料，读取最多四条作品正文；草稿和已下线内容不作为事实来源。
- 最近四轮会话。历史助手依据从当前公开记录重建，不接受客户端助手文字作为事实；此前已看见的内容不能从访客记忆中撤回。
- 服务端流式转发，处理跨数据块的 UTF-8、SSE 与 CRLF，不返回推理过程。只发送普通文本增量和服务端生成的公开作品按钮。
- 页面支持停止生成、关闭会话取消请求、新会话、失败重试；重试不重复用户消息，断流保留已收到内容并标记异常。
- 输入/历史/输出长度、超时、并发和来源地址频率限制；上游认证失败、限额、超时和服务错误均使用中文消息，不透传上游错误正文或配置密钥。
- 公开 `/api/status` 报告模式、模型、是否配置与当前进程最后一次完整模型响应时间；配置或历史成功不等同于当前健康探测，不返回 Key 或内部 API 地址。

模型默认 `deepseek-flash`，采用 `thinking: disabled`。依据 2026-11-05 实际读取的 [DeepSeek 官方 Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)，使用 `POST /chat/completions` 和 SSE。模型可配置，其他服务的兼容性尚未验收。
